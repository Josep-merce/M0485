Pt1 — Sistema de subhastes

Construirem pas a pas una aplicació de subhastes organitzada en classes: usuaris que liciten, subhastes que accepten o rebutgen licitacions i l'execució final que transfereix el crèdit.

1. L'enunciat

Volem un sistema de subhastes on els usuaris puguin licitar per un producte o servei. Aquestes són les regles:

  • Un usuari té un identificador, que no pot canviar, i un crèdit per licitar, que es pot incrementar i decrementar.
  • Una subhasta té un propietari (l'usuari que la crea) i la descripció del producte. Tots dos valors són fixos.
  • Per licitar cal indicar l'usuari i la quantitat. La licitació s'accepta si l'usuari té prou crèdit, no és el propietari i la quantitat supera la licitació major, si n'hi ha. L'operació indica si s'ha acceptat.
  • També es pot licitar sense indicar la quantitat: serà 1 € més que l'última licitació, o 1 € si no n'hi ha cap.
  • Una subhasta recorda totes les licitacions acceptades i es poden consultar. La licitació major és l'última acceptada; si no n'hi ha cap, la consulta retorna null.
  • Una licitació té la subhasta a la qual pertany, la quantitat i l'usuari que l'ha feta. No canvien un cop establertes.
  • Una subhasta es pot tancar: ja no accepta noves licitacions. Una subhasta tancada es pot executar: es resta l'import al guanyador i se suma al propietari. Es pot consultar si està tancada i si s'ha executat.
  • Cada usuari coneix les subhastes de les quals és propietari, les licitacions que li han acceptat i les subhastes que ha guanyat, i les pot consultar.

2. Construcció pas a pas

Fes cada pas en ordre. Intenta escriure el codi tu abans d'obrir la solució, i no passis al pas següent fins que la prova del pas actual doni la sortida esperada.

Abans d'escriure codi, llegim l'enunciat i decidim quines classes necessitem, què guarda cadascuna i quines dades poden canviar. Omple la taula al paper i després compara-la amb aquesta.

Pas 3 Les classes Licitacio i Subhasta

Ara les dues classes centrals. Licitacio només guarda dades fixes. Subhasta conté les regles per acceptar o rebutjar una licitació.

  • Licitacio: atributs final subhasta, usuari i quantitat, un constructor i els tres getters.
  • Subhasta: atributs final propietari i producte, i una ArrayList<Licitacio>.
  • getLicitacioMajor(): retorna l'última licitació acceptada o null si no n'hi ha cap.
  • licitar(Usuari, double): retorna true només si l'usuari té prou crèdit, no és el propietari i la quantitat supera la licitació major (si n'hi ha). Si s'accepta, crea la Licitacio i la guarda.
  • licitar(Usuari) sense quantitat: licita 1 € més que la licitació major, o 1 € si no n'hi ha cap. Fes que cridi l'altre licitar per no repetir codi.
  • getLicitacions(): retorna una còpia de la llista.
📌 Sobrecàrrega: tenim dos mètodes licitar amb el mateix nom i paràmetres diferents. Java tria quin cridar segons els arguments.
📌 usuari == propietari compara si les dues variables apunten al mateix objecte. Aquí és exactament el que volem: saber si qui licita és la mateixa persona que ha creat la subhasta.
✅ Prova-ho:
package subhastes; public class ProvaPas3 { public static void main(String[] args) { Usuari joan = new Usuari("Joan", 100); Usuari pere = new Usuari("Pere", 150); Usuari enric = new Usuari("Enric", 300); Subhasta s = new Subhasta(joan, "Bicicleta"); System.out.println(s.licitar(joan, 20)); // false: és el propietari System.out.println(s.licitar(pere, 500)); // false: no té prou crèdit System.out.println(s.licitar(pere, 40)); // true System.out.println(s.licitar(enric, 30)); // false: no supera els 40 € System.out.println(s.licitar(enric)); // true: licita 41 € Licitacio major = s.getLicitacioMajor(); System.out.println(major.getUsuari().getId() + ": " + major.getQuantitat()); // Enric: 41.0 System.out.println("Licitacions acceptades: " + s.getLicitacions().size()); // 2 } }

package subhastes; public class Licitacio { // Cap d'aquestes propietats pot canviar un cop establerta la licitació private final Subhasta subhasta; private final Usuari usuari; private final double quantitat; public Licitacio(Subhasta subhasta, Usuari usuari, double quantitat) { this.subhasta = subhasta; this.usuari = usuari; this.quantitat = quantitat; } public Subhasta getSubhasta() { return subhasta; } public Usuari getUsuari() { return usuari; } public double getQuantitat() { return quantitat; } }
package subhastes; import java.util.ArrayList; public class Subhasta { private final Usuari propietari; private final String producte; private ArrayList<Licitacio> licitacions = new ArrayList<>(); public Subhasta(Usuari propietari, String producte) { this.propietari = propietari; this.producte = producte; } public Usuari getPropietari() { return propietari; } public String getProducte() { return producte; } /** La licitació major és l'última acceptada (o null si no n'hi ha cap). */ public Licitacio getLicitacioMajor() { if (licitacions.isEmpty()) return null; return licitacions.get(licitacions.size() - 1); } /** Intenta licitar. Retorna true si la licitació s'accepta. */ public boolean licitar(Usuari usuari, double quantitat) { // a) l'usuari ha de tenir prou crèdit if (usuari.getCredit() < quantitat) return false; // b) el propietari no pot licitar a la seva pròpia subhasta if (usuari == propietari) return false; // c) ha de superar la licitació major, si n'hi ha Licitacio major = getLicitacioMajor(); if (major != null && quantitat <= major.getQuantitat()) return false; licitacions.add(new Licitacio(this, usuari, quantitat)); return true; } /** Licitar sense quantitat: 1 € més que l'última, o 1 € si no n'hi ha cap. */ public boolean licitar(Usuari usuari) { Licitacio major = getLicitacioMajor(); double quantitat = (major == null) ? 1 : major.getQuantitat() + 1; return licitar(usuari, quantitat); } /** Retorna una còpia de la llista perquè ningú la pugui modificar des de fora. */ public ArrayList<Licitacio> getLicitacions() { return new ArrayList<>(licitacions); } }
Pas 4 Tancar i executar una subhasta

Una subhasta es pot tancar i, un cop tancada, executar.

  • Afegeix a Subhasta els atributs tancada i executada (inicialment false) amb els seus mètodes de consulta isTancada() i isExecutada().
  • tancar(): a partir d'aquest moment licitar ha de retornar sempre false.
  • executar(): només si la subhasta està tancada, no s'ha executat abans i té alguna licitació. Resta l'import al guanyador, el suma al propietari i marca la subhasta com a executada. Retorna si s'ha pogut executar.
✅ Prova-ho:
package subhastes; public class ProvaPas4 { public static void main(String[] args) { Usuari joan = new Usuari("Joan", 100); Usuari pere = new Usuari("Pere", 150); Subhasta s = new Subhasta(joan, "Bicicleta"); s.licitar(pere, 60); System.out.println(s.executar()); // false: encara no està tancada s.tancar(); System.out.println(s.licitar(pere, 80)); // false: la subhasta està tancada System.out.println(s.executar()); // true System.out.println(s.executar()); // false: ja s'havia executat System.out.println("Joan: " + joan.getCredit()); // Joan: 160.0 System.out.println("Pere: " + pere.getCredit()); // Pere: 90.0 } }

✅ Solució
package subhastes; import java.util.ArrayList; public class Subhasta { private final Usuari propietari; private final String producte; private ArrayList<Licitacio> licitacions = new ArrayList<>(); private boolean tancada = false; // NOU private boolean executada = false; // NOU public Subhasta(Usuari propietari, String producte) { this.propietari = propietari; this.producte = producte; } public Usuari getPropietari() { return propietari; } public String getProducte() { return producte; } public boolean isTancada() { return tancada; } // NOU public boolean isExecutada() { return executada; } // NOU public Licitacio getLicitacioMajor() { if (licitacions.isEmpty()) return null; return licitacions.get(licitacions.size() - 1); } public boolean licitar(Usuari usuari, double quantitat) { if (tancada) return false; // NOU: tancada, no s'accepta res if (usuari.getCredit() < quantitat) return false; if (usuari == propietari) return false; Licitacio major = getLicitacioMajor(); if (major != null && quantitat <= major.getQuantitat()) return false; licitacions.add(new Licitacio(this, usuari, quantitat)); return true; } public boolean licitar(Usuari usuari) { Licitacio major = getLicitacioMajor(); double quantitat = (major == null) ? 1 : major.getQuantitat() + 1; return licitar(usuari, quantitat); } public ArrayList<Licitacio> getLicitacions() { return new ArrayList<>(licitacions); } /** NOU: a partir d'ara no s'accepten més licitacions. */ public void tancar() { tancada = true; } /** * NOU: només es pot executar una subhasta tancada, no executada abans * i amb alguna licitació. Retorna true si s'ha executat. */ public boolean executar() { Licitacio guanyadora = getLicitacioMajor(); if (!tancada || executada || guanyadora == null) return false; guanyadora.getUsuari().decrementarCredit(guanyadora.getQuantitat()); propietari.incrementarCredit(guanyadora.getQuantitat()); executada = true; return true; } }
Pas 5 Associacions: què coneix cada usuari

L'enunciat diu que els usuaris coneixen les seves subhastes, les seves licitacions acceptades i les subhastes que han guanyat. Afegim aquestes associacions.

  • A Usuari, tres llistes: subhastes pròpies, licitacions acceptades i subhastes guanyades, amb els seus getters (que retornin còpies).
  • Tres mètodes per afegir-hi elements, sense modificador de visibilitat: així només els poden cridar les classes del paquet subhastes.
  • A Subhasta: el constructor registra la subhasta al propietari, licitar registra la licitació acceptada a l'usuari i executar registra la subhasta guanyada al guanyador.
⚠️ Per què no fem públics els mètodes d'afegir? Si ho fossin, des del main es podria fer pere.afegirSubhastaGuanyada(s) sense haver guanyat res. Amb la visibilitat de paquet, només Subhasta pot establir aquestes associacions, en el moment correcte.

Pas 6 Programa principal

Escriu la classe Main amb el programa de l'enunciat:

  • Crea els usuaris Joan, Pere i Enric amb 100, 150 i 300 € de crèdit.
  • Crea una subhasta de Joan per a un "Telèfon Mòbil".
  • Pere licita 100 €. Mostra la licitació major (producte, usuari i quantitat).
  • Enric licita 50 €. Mostra la licitació major i comprova que no s'ha acceptat.
  • Tanca la subhasta. Enric licita 200 € i comprova que no s'accepta.
  • Executa la subhasta i mostra el crèdit dels tres usuaris.
  • Per a cada usuari, mostra les subhastes pròpies, les guanyades (només el producte) i les licitacions acceptades (producte i quantitat).
✅ Pista: crea mètodes static auxiliars al Main (per exemple mostrarInfo(Usuari u)) per no repetir el mateix codi tres vegades.
