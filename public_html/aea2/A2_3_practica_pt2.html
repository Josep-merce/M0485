Pt2 — Jocs de números

Construirem pas a pas una col·lecció de jocs d'endevinar números organitzada en una jerarquia de classes, amb una classe abstracta, una interfície i paquets. Al final, una aplicació deixarà triar a quin joc vols jugar.

M0485 Programació› AEA2 — Programació orientada a objectes› Pt2 — Jocs de números

1. Què construirem

Una aplicació amb diversos jocs d'endevinar números. Tots els jocs tenen vides i un rècord comú, però cadascun té les seves pròpies regles: quins números es poden dir i quan s'ha guanyat. Aprofitarem l'herència perquè cada joc només hagi d'escriure el que el fa diferent, i una interfície perquè l'aplicació pugui tractar tots els jocs igual.

2. Construcció pas a pas

Fes cada pas en ordre. Intenta escriure el codi tu abans d'obrir la solució, i no passis al pas següent fins que la prova del pas actual funcioni.

Pas 1 Anàlisi: la jerarquia de jocs

Abans de programar, mirem com s'organitzen les classes. Cada joc concret hereta el que necessita de les classes que té per sobre.

📌 Jerarquia de classes al final de la pràctica:
Joc (abstracta) — vides, vides inicials, rècord (static)
   └── JocNumeros (abstracta, implementa Jugable) — la partida: demanar números, validar-los i restar vides
        ├── JocEndevinaNumero — cal endevinar un número entre 0 i 10
        │      ├── JocEndevinaParell — només accepta números parells
        │      └── JocEndevinaSenar — només accepta números senars
        └── JocEndevinaMultiplicacio — cal endevinar el resultat d'una multiplicació

Jugable (interfície) — juga(), mostraNom(), mostraInfo()

Pas 2 La classe d'utilitat Teclat

Els jocs han de llegir números del teclat. Fem una classe d'utilitat amb mètodes estàtics perquè tot el programa comparteixi un sol Scanner. Aquesta classe ja te la donem feta: copia-la al paquet jocs.

📌 La lectura de teclat amb Scanner s'estudia a fons a l'RA5. Aquí només cal saber fer servir els dos mètodes d'aquesta classe: Teclat.llegirEnter(missatge) i Teclat.llegirText(missatge).
package jocs; import java.util.Scanner; /** * Classe d'utilitat per llegir del teclat. Tots els jocs i l'aplicació * comparteixen el mateix Scanner (no n'hem de crear més d'un sobre System.in). */ public class Teclat { private static final Scanner ENTRADA = new Scanner(System.in); private Teclat() { } // no s'han de crear objectes Teclat /** Mostra el missatge i llegeix un enter. Si no és un número, el torna a demanar. */ public static int llegirEnter(String missatge) { while (true) { System.out.print(missatge); String linia = ENTRADA.nextLine().trim(); try { return Integer.parseInt(linia); } catch (NumberFormatException e) { System.out.println("Això no és un número. Torna-ho a provar."); } } } /** Mostra el missatge i llegeix una línia de text. */ public static String llegirText(String missatge) { System.out.print(missatge); return ENTRADA.nextLine().trim(); } }
📌 llegirEnter fa servir el control d'excepcions que vas veure a l'AEA1: si l'usuari escriu una cosa que no és un número, Integer.parseInt llança una NumberFormatException i el mètode torna a demanar el valor.

Pas 3 La classe abstracta Joc

La classe Joc conté el que tenen en comú tots els jocs. És abstracta: sabem que tots els jocs es juguen i que en tots es pot guanyar, però no sabem com. Això ho decidirà cada subclasse.

  • Atributs private: vides (les que queden) i videsInicials (final, per poder reiniciar).
  • Atribut de classe private static int record = 0: és comú a tots els jocs.
  • Constructor amb el nombre de vides inicials, com a màxim 10.
  • mostraVidesRestants(), treuVida() (retorna si encara queden vides) i reiniciaPartida().
  • actualitzaRecord(): la puntuació és 10 - vides gastades. Si iguala el rècord, ho diu; si el supera, l'actualitza i mostra el nou valor; si és menor, no fa res.
  • Mètodes abstractes juga() i heGuanyat().
⚠️ Comprova-ho: si escrius Joc j = new Joc(3); el compilador dona l'error "Joc is abstract; cannot be instantiated". És el que volem: no existeix un "joc en general".
CA: 7.1 · 7.2
✅ Solució
package jocs; /** Classe base de tots els jocs. És abstracta: no es poden crear objectes Joc. */ public abstract class Joc { private static final int MAX_VIDES = 10; private int vides; // vides que queden a la partida actual private final int videsInicials; // per poder reiniciar la partida private static int record = 0; // atribut de classe: comú a tots els jocs public Joc(int vides) { if (vides > MAX_VIDES) vides = MAX_VIDES; if (vides < 1) vides = 1; this.vides = vides; this.videsInicials = vides; } public void mostraVidesRestants() { if (vides == 1) System.out.println("Et queda 1 vida."); else System.out.println("Et queden " + vides + " vides."); } /** Treu una vida i retorna si encara en queden. */ public boolean treuVida() { vides--; return vides > 0; } public void reiniciaPartida() { vides = videsInicials; } /** Només s'ha de cridar quan el jugador ha guanyat. */ public void actualitzaRecord() { int videsGastades = videsInicials - vides; int puntuacio = 10 - videsGastades; if (puntuacio == record) { System.out.println("Has igualat el rècord: " + record + " punts."); } else if (puntuacio > record) { record = puntuacio; System.out.println("Has batut el rècord! Nou rècord: " + record + " punts."); } // si és menor, no fem res } /** Aquí no sabem com es juga: ho decidirà cada subclasse. */ public abstract void juga(); /** Tampoc sabem quan s'ha guanyat. */ public abstract boolean heGuanyat(); }
Pas 4 JocNumeros i JocEndevinaNumero

JocNumeros generalitza tots els jocs en què s'ha d'endevinar un número. Encara no sap quin número és el correcte, per això també és abstracta. JocEndevinaNumero ja és un joc concret.

  • JocNumeros (abstracta, filla de Joc): atribut protected int numeroUsuari i constructor que rep les vides.
  • Implementa juga(): reinicia la partida i, en bucle, demana un número. Si validaNumero() retorna fals, el torna a demanar sense restar vida. Si heGuanyat() és cert, mostra un missatge, crida actualitzaRecord() i acaba. Si no, crida treuVida(): si encara queden vides, deixa tornar-ho a intentar; si no, acaba.
  • validaNumero(int): en aquesta classe sempre retorna cert.
  • JocEndevinaNumero (filla de JocNumeros): constructor amb les vides i el número secret (entre 0 i 10). Sobreescriu heGuanyat().
📌 Fixa't: juga() crida heGuanyat(), que a JocNumeros encara no està escrit. Quan el joc sigui un JocEndevinaNumero, Java executarà la versió de JocEndevinaNumero. Això és polimorfisme.
✅ Prova-ho: crea ProvaPas4 al paquet jocs.aplicacio.
package jocs.aplicacio; import jocs.numeros.JocEndevinaNumero; public class ProvaPas4 { public static void main(String[] args) { JocEndevinaNumero joc = new JocEndevinaNumero(3, 7); // 3 vides, secret 7 joc.juga(); joc.juga(); // segona partida: el rècord es compara amb l'anterior } }

package jocs.numeros; import jocs.Joc; import jocs.Teclat; /** Generalitza els jocs en què cal endevinar un número. No s'instancia. */ public abstract class JocNumeros extends Joc { protected int numeroUsuari; // l'últim número vàlid introduït public JocNumeros(int vides) { super(vides); } @Override public void juga() { reiniciaPartida(); while (true) { int numero = Teclat.llegirEnter("Introdueix un número: "); if (!validaNumero(numero)) { continue; // número no vàlid: no es resta vida } numeroUsuari = numero; if (heGuanyat()) { System.out.println("Encertat! Has guanyat."); actualitzaRecord(); return; } if (treuVida()) { System.out.println("No és correcte."); mostraVidesRestants(); } else { System.out.println("No et queden vides. Has perdut."); return; } } } /** Per defecte qualsevol número és vàlid. Les subclasses ho poden canviar. */ public boolean validaNumero(int numero) { return true; } }
package jocs.numeros; public class JocEndevinaNumero extends JocNumeros { protected int numeroSecret; // entre 0 i 10 public JocEndevinaNumero(int vides, int numeroSecret) { super(vides); if (numeroSecret < 0) numeroSecret = 0; if (numeroSecret > 10) numeroSecret = 10; this.numeroSecret = numeroSecret; } @Override public boolean heGuanyat() { return numeroUsuari == numeroSecret; } }
Pas 5 JocEndevinaParell i JocEndevinaSenar

Dues variants que només canvien una regla: quins números són vàlids.

  • JocEndevinaParell (filla de JocEndevinaNumero): sobreescriu validaNumero(). Retorna cert si el número és parell; si no, mostra un missatge i retorna fals.
  • JocEndevinaSenar: igual, però per als números senars.
  • Tots dos constructors reben les vides i el número secret, i criden super(...).
⚠️ El número secret d'un JocEndevinaParell ha de ser parell (i el d'un JocEndevinaSenar, senar). Si no, el jugador no podria guanyar mai.
✅ Prova-ho:
package jocs.aplicacio; import jocs.numeros.JocEndevinaParell; import jocs.numeros.JocEndevinaSenar; public class ProvaPas5 { public static void main(String[] args) { System.out.println("--- Parell (secret 4) ---"); new JocEndevinaParell(3, 4).juga(); System.out.println("--- Senar (secret 9) ---"); new JocEndevinaSenar(3, 9).juga(); } }
--- Parell (secret 4) --- Introdueix un número: 3 El número ha de ser parell. Introdueix un número: 2 No és correcte. Et queden 2 vides. Introdueix un número: 4 Encertat! Has guanyat. Has batut el rècord! Nou rècord: 9 punts. --- Senar (secret 9) --- Introdueix un número: 6 El número ha de ser senar. Introdueix un número: 9 Encertat! Has guanyat. Has batut el rècord! Nou rècord: 10 punts.
📌 El rècord és compartit: al joc parell s'ha fet un rècord de 9 punts i al senar s'ha batut amb 10. Són objectes diferents, però record és static: només n'hi ha un per a tota la classe Joc.

Pas 6 JocEndevinaMultiplicacio

Aquest joc consisteix a endevinar el resultat de multiplicar dos números aleatoris que no coneixem.

  • JocEndevinaMultiplicacio és filla de JocNumeros (no de JocEndevinaNumero: no hi ha cap número secret entre 0 i 10).
  • Atributs nombre1, nombre2 i resultat.
  • El constructor rep les vides i el nivell de dificultat. Te'l donem fet:
public JocEndevinaMultiplicacio(int vides, int nivell) { super(vides); int max; switch (nivell) { case 1 -> max = 5; // Fàcil case 2 -> max = 10; // Mitjà default -> max = 15; // Difícil } this.nombre1 = (int) (Math.random() * max) + 1; this.nombre2 = (int) (Math.random() * max) + 1; this.resultat = nombre1 * nombre2; }
  • Sobreescriu heGuanyat(): s'ha guanyat si el número de l'usuari és igual al resultat.
📌 Math.random() retorna un double entre 0 (inclòs) i 1 (no inclòs). En multiplicar-lo per max, convertir-lo a int i sumar-hi 1, obtenim un enter entre 1 i max.
✅ Prova-ho:
package jocs.aplicacio; import jocs.numeros.JocEndevinaMultiplicacio; public class ProvaPas6 { public static void main(String[] args) { // Nivell 1: els dos números són entre 1 i 5, el resultat entre 1 i 25 new JocEndevinaMultiplicacio(5, 1).juga(); } }

Pas 7 La interfície Jugable

Volem poder tractar tots els jocs de la mateixa manera, siguin de números o d'un altre tipus que fem més endavant. Definim un contracte comú: la interfície Jugable.

  • Crea el paquet jocs.interficies i, a dins, la interfície Jugable amb els mètodes juga(), mostraNom() (mostra el nom del joc) i mostraInfo() (explica com es juga).
  • Treu el mètode abstracte juga() de Joc. La classe continua sent abstracta: no volem que se'n creïn objectes.
  • JocNumeros declara implements Jugable. El seu juga() ara compleix el contracte de la interfície.
  • Els quatre jocs concrets implementen mostraNom() i mostraInfo().
  • Comenta amb Javadoc la interfície i les classes.
📌 Per què JocNumeros no ha d'implementar mostraNom()? Perquè és abstracta: una classe abstracta pot deixar mètodes de la interfície sense implementar. Els han d'implementar obligatòriament les seves subclasses concretes.
CA: 7.2 · 7.8 · 7.9

Pas 8 L'aplicació

Per acabar, la classe Aplicacio al paquet jocs.aplicacio.

  • public static Jugable triaJoc(): crea un objecte de cadascun dels quatre jocs i una ArrayList<Jugable> amb tots quatre. A partir d'aquí només treballa amb la llista.
  • Mostra un menú amb el nom dels jocs i demana un número entre 0 i 3. Si no és vàlid, el torna a demanar.
  • Retorna el joc triat.
  • main: crida triaJoc(), després mostraNom(), mostraInfo() i juga(). Quan acaba la partida, pregunta si es vol tornar a jugar i, si la resposta és afirmativa, ho repeteix tot.
📌 La clau de la interfície: Aplicacio no sap de quina classe és cada joc. Només sap que tots són Jugable. Si demà afegim un joc de paraules que implementi Jugable, el main no canvia gens.
✅ Pista: per obtenir números secrets parells entre 0 i 10 pots fer 2 * r.nextInt(6); per als senars, 2 * r.nextInt(5) + 1.
CA: 7.7 · 7.9
✅ Solució
package jocs.aplicacio; import java.util.ArrayList; import java.util.Random; import jocs.Teclat; import jocs.interficies.Jugable; import jocs.numeros.JocEndevinaMultiplicacio; import jocs.numeros.JocEndevinaNumero; import jocs.numeros.JocEndevinaParell; import jocs.numeros.JocEndevinaSenar; public class Aplicacio { /** Mostra el menú i retorna el joc triat per l'usuari. */ public static Jugable triaJoc() { Random r = new Random(); // Un objecte de cada joc JocEndevinaNumero j0 = new JocEndevinaNumero(5, r.nextInt(11)); // 0..10 JocEndevinaParell j1 = new JocEndevinaParell(5, 2 * r.nextInt(6)); // 0, 2, ..., 10 JocEndevinaSenar j2 = new JocEndevinaSenar(5, 2 * r.nextInt(5) + 1); // 1, 3, ..., 9 JocEndevinaMultiplicacio j3 = new JocEndevinaMultiplicacio(5, 1); // A partir d'aquí només treballem amb la llista de Jugable ArrayList<Jugable> jocs = new ArrayList<>(4); jocs.add(j0); jocs.add(j1); jocs.add(j2); jocs.add(j3); System.out.println("\n===== JOCS ====="); for (int i = 0; i < jocs.size(); i++) { System.out.print(i + " - "); jocs.get(i).mostraNom(); } int opcio = Teclat.llegirEnter("Tria un joc (0-3): "); while (opcio < 0 || opcio > 3) { opcio = Teclat.llegirEnter("Opció no vàlida. Tria un joc (0-3): "); } return jocs.get(opcio); } public static void main(String[] args) { String resposta; do { Jugable joc = triaJoc(); joc.mostraNom(); joc.mostraInfo(); joc.juga(); resposta = Teclat.llegirText("Vols jugar de nou? (s/n): "); } while (resposta.equalsIgnoreCase("s")); System.out.println("Fins aviat!"); } }
