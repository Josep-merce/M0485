Conversió implícita

Quan Java canvia el tipus tot sol

Sovint cal passar un valor d'un tipus a un altre. Hi ha tres situacions: la conversió implícita (automàtica), la explícita (casting) i la conversió entre text i números.

TipusCal escriure res?Pot perdre informació?
Implícita (de petit a gran)No, Java la fa solaNo
Explícita / casting (de gran a petit)Sí: (tipus) valorSí: decimals o desbordament
Text ↔ númeroSí: Integer.parseInt(), String.valueOf()…Pot fallar si el text no és un número
BàsicConversions automàtiques
public class ConversioImplicita { public static void main(String[] args) { int alumnes = 30; double mitjana = 7.5; double suma = alumnes * mitjana; // alumnes es converteix a double long gran = alumnes; // int → long, automàtic char lletra = 'A'; int codi = lletra; // char → int: codi Unicode System.out.println(suma); // 225.0 System.out.println(gran); // 30 System.out.println(codi); // 65 } }
🖥️ Sortida per consola
225.0
30
65
Com funciona

Quan en una operació es barregen un int i un double, Java converteix l'int a double abans d'operar: per això suma és 225.0. Guardar un int en un long també és automàtic, perquè un long és més gran i no es perd res.

Un char és, per dins, un número: el codi Unicode del caràcter. Guardat en un int, 'A' es mostra com a 65.

👀 Fixa't-hi

Sentit de la conversió implícita: byte → short → int → long → float → double. En sentit contrari cal fer casting.

Conversió explícita (casting)

Quan som nosaltres qui forcem el canvi

Per passar d'un tipus gran a un de més petit cal indicar-ho escrivint el tipus de destinació entre parèntesis: (int) 9.99. Amb això diem al compilador «ja sé que puc perdre informació».

MitjàCasting: truncament i desbordament
public class Casting { public static void main(String[] args) { double preu = 19.99; int preuEnter = (int) preu; // cal indicar (int) System.out.println(preuEnter); // 19 → trunca, NO arrodoneix long arrodonit = Math.round(preu); System.out.println(arrodonit); // 20 → arrodoneix int gran = 130; byte petit = (byte) gran; // byte només arriba a 127 System.out.println(petit); // -126 → desbordament! int codi = 66; char lletra = (char) codi; System.out.println(lletra); // B } }
🖥️ Sortida per consola
19
20
-126
B
Com funciona

(int) 19.99 no arrodoneix: talla els decimals i queda 19. Si volem arrodonir, fem servir Math.round, que dona 20.

Un byte només arriba a 127. En forçar-hi 130, el valor «dona la volta» pel costat negatiu i surt −126: és un desbordament, i Java no avisa. L'últim cas fa el camí invers de l'apartat anterior: el codi 66 és la lletra B.

AvançatObtenir una mitjana decimal a partir d'enters
public class MitjanaEnters { public static void main(String[] args) { int suma = 17; int quantitat = 2; double malament = suma / quantitat; // 8.0 → la divisió ja és entera! double be = (double) suma / quantitat; // 8.5 → convertim abans de dividir System.out.println("Malament: " + malament); System.out.println("Bé: " + be); // Arrodonir a 2 decimals: multipliquem, arrodonim i tornem a dividir double preu = 10.0 / 3; // 3.3333333333333335 double preu2 = Math.round(preu * 100) / 100.0; System.out.println("Preu: " + preu2); // 3.33 } }
🖥️ Sortida per consola
Malament: 8.0
Bé: 8.5
Preu: 3.33
Com funciona

A malament, 17 / 2 es fa entre enters i dona 8; després es guarda en un double i passa a ser 8.0, però els decimals ja s'han perdut. A be, el casting converteix suma a double abans de dividir, i la divisió ja és decimal.

Per arrodonir a 2 decimals: 3.333… * 100 = 333.33…, Math.round el deixa en 333 i, en dividir per 100.0 (decimal!), queda 3.33.

⚠️ Errors típics

El casting trunca: (int) 9.99 dona 9. Per arrodonir usa Math.round(). I compte amb l'ordre: (double) (17 / 2) dona 8.0 perquè la divisió entera es fa abans del casting.

👀 Fixa't-hi

Els decimals no sempre són exactes. Els tipus double i float guarden els números en binari i alguns valors no es poden representar exactament: 0.1 + 0.2 dona 0.30000000000000004. Per això arrodonim els imports amb Math.round(x * 100) / 100.0.

Conversió entre text i números

Quan un número arriba com a text

Un text com "42" no és un número: no es pot sumar ni multiplicar. Per operar-hi cal convertir-lo, i a l'inrevés, de vegades volem un número com a text.

ConversióCom es faExempleResultat
String → intInteger.parseInt(text)Integer.parseInt("42")42
String → doubleDouble.parseDouble(text)Double.parseDouble("3.5")3.5
String → booleanBoolean.parseBoolean(text)Boolean.parseBoolean("true")true
número → StringString.valueOf(n)String.valueOf(42)"42"
número → Stringconcatenar amb """" + 3.5"3.5"
MitjàConvertir text a número per poder operar
public class TextANumero { public static void main(String[] args) { String textQuantitat = "3"; String textPreu = "12.5"; // "3" + "12.5" seria "312.5": cal convertir-los abans d'operar int quantitat = Integer.parseInt(textQuantitat); double preu = Double.parseDouble(textPreu); double total = quantitat * preu; String missatge = "Total: " + String.valueOf(total); System.out.println(textQuantitat + textPreu); // 312.5 (concatenació) System.out.println(missatge); // Total: 37.5 } }
🖥️ Sortida per consola
312.5
Total: 37.5
Com funciona

Si sumem els dos textos tal com estan, el + els enganxa i surt 312.5, que sembla un número però no ho és. Integer.parseInt i Double.parseDouble llegeixen el text i en treuen el número, i amb aquests ja es pot multiplicar.

String.valueOf fa el camí contrari: converteix el resultat a text.

👀 Fixa't-hi

Si el text no representa un número (per exemple Integer.parseInt("hola")), el programa s'atura amb una NumberFormatException. A l'A3 aprendrem a controlar aquests errors amb try-catch.

// Converteix a número les dades d'un formulari, que arriben com a text public class Formulari { public static void main(String[] args) { // Dades tal com arriben del formulari: tot és text String textEdat = "17"; String textAlcada = "1.7"; String textSoci = "true"; // Convertim el text al tipus que necessitem per operar int edat = Integer.parseInt(textEdat); double alcada = Double.parseDouble(textAlcada); boolean soci = Boolean.parseBoolean(textSoci); int edatVinent = edat + 1; double alcadaCm = alcada * 100; System.out.println("L'any vinent tindrà " + edatVinent + " anys"); System.out.println("Alçada: " + alcadaCm + " cm"); System.out.println("Soci: " + soci); // I a l'inrevés: de número a text String codi = String.valueOf(edatVinent) + "A"; System.out.println("Codi de grup: " + codi); } }

Composició seqüencial d'instruccions

Dades → procés → sortida

La composició seqüencial és l'estructura més simple: les instruccions s'executen una rere l'altra, de dalt a baix, cadascuna una sola vegada. Tots els programes que hem fet fins ara són seqüencials. Tenen sempre tres parts: dades d'entrada → procés → sortida.

ALGORISME PreuAmbIva DADES: preu = 25, IVA = 0.21 ← entrada CÀLCUL: total ← preu × (1 + IVA) ← procés ESCRIURE "Total: ", total ← sortida FI ALGORISME
BàsicL'algorisme PreuAmbIva en Java
public class PreuAmbIva { public static void main(String[] args) { // Dades d'entrada final double IVA = 0.21; double preu = 25; // Procés double total = preu * (1 + IVA); // Sortida System.out.println("Total: " + total); } }
🖥️ Sortida per consola
Total: 30.25
Com funciona

Cada línia del pseudocodi es converteix en una o dues instruccions Java, en el mateix ordre. El programa no pren cap decisió ni repeteix res: s'executa de dalt a baix una sola vegada.

L'ordre de les instruccions importa

En un algorisme seqüencial, cada instrucció fa servir els valors que han deixat les anteriors. Si canviem l'ordre, el resultat canvia. L'exemple clàssic és intercanviar el valor de dues variables: cal una variable auxiliar.

MitjàIntercanviar dues variables
public class Intercanvi { public static void main(String[] args) { int a = 5; int b = 9; System.out.println("Abans: a = " + a + ", b = " + b); // Malament: a = b; b = a; → les dues acabarien valent 9 int aux = a; // 1. guardem el valor d'a a = b; // 2. a rep el valor de b b = aux; // 3. b rep el valor original d'a System.out.println("Després: a = " + a + ", b = " + b); } }
🖥️ Sortida per consola
Abans:   a = 5, b = 9
Després: a = 9, b = 5
Com funciona

Si fem directament a = b;, el 5 que hi havia a a es perd per sempre, i b = a; hi tornaria a posar un 9. Per això primer el guardem a aux. És com intercanviar el contingut de dos gots: cal un tercer got.

✅ Bon costum

Abans de programar, escriu en paper les tres parts (dades, procés i sortida) i en quin ordre s'han de calcular els valors: un valor només es pot fer servir després d'haver-lo calculat.

aux <- a · a <- b · b <- auxint aux = a; · a = b; · b = aux;

// Genera el tiquet d'una compra de material escolar amb l'IVA public class TiquetIva { public static void main(String[] args) { // Dades d'entrada final double IVA = 0.21; int llibretes = 3; double preuLlibreta = 2.40; int boligrafs = 2; double preuBoligraf = 1.15; // Procés double base = llibretes * preuLlibreta + boligrafs * preuBoligraf; double importIva = base * IVA; double total = base + importIva; // Arrodonim els imports a 2 decimals base = Math.round(base * 100) / 100.0; importIva = Math.round(importIva * 100) / 100.0; total = Math.round(total * 100) / 100.0; // Sortida System.out.println("-----------------------"); System.out.println(llibretes + " x Llibreta " + preuLlibreta + " €"); System.out.println(boligrafs + " x Bolígraf " + preuBoligraf + " €"); System.out.println("-----------------------"); System.out.println("Base: " + base + " €"); System.out.println("IVA: " + importIva + " €"); System.out.println("TOTAL: " + total + " €"); System.out.println("-----------------------"); } }
✔ Què es valora
  • L'IVA és una constant i els imports s'arrodoneixen correctament.
  • Math.round(x * 100) / 100, sense el .0, faria una divisió entera i perdria els decimals: 950 / 100 = 9.
  • L'ordre importa: el total es calcula a partir de la base i l'IVA. Si es calcula abans, el compilador diu que base encara no existeix.
  • Les tres parts (dades, procés i sortida) estan separades amb comentaris.

Sortida per pantalla i seqüències d'escapament

Caràcters especials dins dels textos

print i println accepten qualsevol expressió i la converteixen automàticament a text. Cada instrucció escriu just on s'ha quedat l'anterior. Dins d'un text, la contrabarra \ introdueix una seqüència d'escapament: un caràcter especial que no es pot escriure directament.

Bàsicprint, println i seqüències d'escapament
public class SortidaPantalla { public static void main(String[] args) { System.out.print("Hola "); System.out.print("a tothom"); System.out.println(); // només salta de línia System.out.println("Producte\tPreu"); System.out.println("Llibreta\t2.4 €"); System.out.println("Diu: \"Aprendre Java és divertit\""); System.out.println("Ruta: C:\\Usuaris\\alumne"); System.out.println("Línia 1\nLínia 2"); System.out.println(3 + 4); // expressió numèrica: 7 System.out.println('a'); // caràcter } }
🖥️ Sortida per consola
Hola a tothom
Producte	Preu
Llibreta	2.4 €
Diu: "Aprendre Java és divertit"
Ruta: C:\Usuaris\alumne
Línia 1
Línia 2
7
a
Com funciona

\t insereix una tabulació (per això Preu i 2.4 € surten alineats), \" permet posar cometes dins d'un text sense tancar-lo, \\ escriu una sola contrabarra i \n salta de línia enmig del text.

Les dues últimes línies mostren que println també accepta expressions (calcula 3 + 4 i mostra 7) i caràcters.

parseInt converteix el text en el número 12, que se suma amb 3.
Demo 2Implícita o explícita?Mitjà

Per a cada assignació, decideix si Java fa la conversió sol (implícita) o si cal escriure un casting (explícita).

1. double d = 5;
Un int cap sense problemes en un double: Java el converteix sol.
2. int n = 5.7;
De double a int es perden decimals: cal (int) 5.7, que dona 5.
3. long l = 100;
D'int a long (més gran): automàtic.
4. int i = 100L;
100L és un long; per guardar-lo en un int cal (int) 100L.
5. float f = 10;
Un enter es pot guardar en un float automàticament.
6. int c = 'A';
Un char es converteix sol al seu codi (65).
7. byte b = 200;
200 no cap en un byte: el compilador obliga a escriure (byte) 200 (i donaria −56).
8. float f = 2.5;
2.5 és double, més gran que float: cal (float) 2.5 o escriure 2.5f.
Demo 3Detecta l'errorMitjà

Els tres programes compilen, però el resultat no és el que esperàvem. El culpable sempre és el mateix: la divisió entera.

a) Volem la mitjana de 7, 8 i 8 amb decimals (7.67).
public class Mitjana { public static void main(String[] args) { int suma = 7 + 8 + 8; double mitjana = (double) (suma / 3); System.out.println(mitjana); } }
🔎 L'error
El parèntesi fa primer la divisió entera 23 / 3 = 7 i després la converteix a 7.0. El casting s'ha d'aplicar a suma, abans de dividir.
🖥️ Sortida que dona (incorrecta)
7.0
✅ Versió corregida
public class Mitjana { public static void main(String[] args) { int suma = 7 + 8 + 8; double mitjana = (double) suma / 3; System.out.println(mitjana); } }
🖥️ Sortida per consola
7.666666666666667
b) Volem el percentatge de 45 respostes correctes sobre 60 (75.0 %).
public class Percentatge { public static void main(String[] args) { double percentatge = 45 / 60 * 100; System.out.println(percentatge + " %"); } }
🔎 L'error
45 / 60 són dos enters: la divisió entera dona 0, i 0 · 100 = 0. Que el resultat es guardi en un double no canvia res, perquè el càlcul ja s'ha fet. N'hi ha prou que un operand sigui decimal.
🖥️ Sortida que dona (incorrecta)
0.0 %
✅ Versió corregida
public class Percentatge { public static void main(String[] args) { double percentatge = 45.0 / 60 * 100; System.out.println(percentatge + " %"); } }
🖥️ Sortida per consola
75.0 %
c) Volem repartir 10 € entre 4 persones (2.5 € cadascuna).
public class Repartiment { public static void main(String[] args) { int total = 10; int persones = 4; double perCap = total / persones; System.out.println(perCap + " € per persona"); } }
🔎 L'error
total / persones és una divisió entre dos int: dona 2, que es guarda com a 2.0. Cal convertir un dels dos operands abans de dividir.
🖥️ Sortida que dona (incorrecta)
2.0 € per persona
✅ Versió corregida
public class Repartiment { public static void main(String[] args) { int total = 10; int persones = 4; double perCap = (double) total / persones; System.out.println(perCap + " € per persona"); } }
🖥️ Sortida per consola
2.5 € per persona
