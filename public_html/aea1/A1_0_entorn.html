Què és Java?

El llenguatge que farem servir durant el curs

  • Java és un llenguatge de programació: una manera d'escriure ordres que l'ordinador pot entendre i executar.
  • Va néixer el 1995 i el seu lema és «Escriu una vegada, executa a qualsevol lloc»: el mateix programa funciona a Windows, macOS i Linux.
  • Serveix per fer aplicacions de tot tipus: webs (la part del servidor), apps d'Android, programes d'escriptori i sistemes d'empreses i bancs.
  • És un dels llenguatges més demandats a les empreses, i per això és la base del mòdul de Programació de DAW.

Java: JDK, JRE i JVM

Les peces que necessitem per programar i executar

Per treballar amb Java fan falta tres peces, una dins de l'altra:

ComponentNom completPer a què serveix
JDKJava Development KitEines per desenvolupar: compilador (javac), JRE i eines de depuració.
JREJava Runtime EnvironmentEntorn per executar programes Java. Inclou la JVM i les llibreries estàndard.
JVMJava Virtual MachineMàquina virtual que executa el bytecode traduint-lo a instruccions del sistema operatiu.

Escrivim el programa en un fitxer .java, que és text. El compilador javac comprova que estigui ben escrit i, si no hi ha errors, genera un fitxer .class amb el bytecode, un codi intermedi que no depèn de cap sistema operatiu. La JVM llegeix aquest bytecode i l'executa a l'ordinador concret.

Per això el mateix .class funciona a Windows, macOS i Linux: cada sistema té la seva JVM. A NetBeans tot el procés es fa amb un sol clic (Run File).

Primer projecte Maven: Hola Món

Crear el projecte, la classe i executar-la

Projecte Maven «Hola món» a NetBeans, pas a pas. Crear projectes és el primer pas per desenvolupar qualsevol aplicació.

Què treballem: RA1: CA 1.1 (blocs del programa), 1.2 (crear projectes), 1.3 (utilitzar l'IDE) i 1.9 (comentaris). RA2: CA 2.9 (usar l'IDE per crear i compilar programes simples).

Requisits previs

  • JDK instal·lat, en una versió LTS (al curs fem servir la 21; també serveix la 25). Ho pots comprovar a la consola amb java -version.
  • Apache NetBeans, en una versió recent. Ja porta Maven integrat, així que no cal instal·lar-lo a part.

Pas 1 – Crear el projecte

  • Menú File → New Project… (o Ctrl+Maj+N).
  • A Categories tria Java with Maven i a Projects tria Java Application.
  • Clica Next.

Pas 2 – Configurar el projecte

Clica Finish. La primera vegada, Maven pot trigar una mica perquè descarrega dependències.

👀 Fixa't-hi

En prémer Finish, NetBeans crea automàticament la classe principal amb el nom del projecte (HolaMon.java), amb el mètode main i un Hello World! ja escrits. No cal crear-la a mà: només l'has d'editar al pas 5.

✅ Bones pràctiques

Fes servir sempre el mateix Group Id (el que us indiqui el professorat). Així tots els projectes del grup tenen la mateixa estructura de paquets.

Pas 3 – Entendre l'estructura generada

A la pestanya Files (Ctrl+2) es veu l'estructura real del projecte. Maven organitza sempre els fitxers de la mateixa manera, i per això qualsevol IDE (NetBeans, IntelliJ, VS Code) o la terminal saben obrir i executar el projecte sense canviar res.

HolaMon/ ← carpeta del projecte (porta el nom del Project Name) ├── pom.xml ← configuració Maven: Group Id, versió de Java, classe principal… ├── src/ ← carpeta de tot el codi que escrivim nosaltres │ ├── main/java/ ← codi font del programa (el que es compila i s'executa) │ │ └── daw/holamon/ ← carpetes del paquet daw.holamon (Group Id + nom del projecte) │ │ └── HolaMon.java ← classe principal amb el main, creada per NetBeans │ └── test/java/ ← proves automàtiques (JUnit); de moment no la fem servir └── target/ ← resultat de compilar (.class, .jar); la crea Maven, no s'edita

Fixa't que cada paquet correspon a una carpeta: el paquet daw.holamon són les carpetes daw/holamon.

Pas 4 – Revisar el pom.xml

NetBeans genera un pom.xml semblant a aquest:

<?xml version="1.0" encoding="UTF-8"?> <project xmlns="http://maven.apache.org/POM/4.0.0" xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 http://maven.apache.org/xsd/maven-4.0.0.xsd"> <modelVersion>4.0.0</modelVersion> <groupId>daw</groupId> <artifactId>HolaMon</artifactId> <version>1.0-SNAPSHOT</version> <packaging>jar</packaging> <properties> <project.build.sourceEncoding>UTF-8</project.build.sourceEncoding> <maven.compiler.release>21</maven.compiler.release> <exec.mainClass>daw.holamon.HolaMon</exec.mainClass> </properties> </project>

Hi ha dues línies clau:

  • maven.compiler.release és la versió de Java amb què es compila. Ha de coincidir amb el JDK instal·lat o ser inferior.
  • exec.mainClass indica quina classe s'executa amb Run.

Pas 5 – Escriure el codi

Obre HolaMon.java (a Source Packages) i deixa'l així:

package daw.holamon; /** * Primer programa en Java: mostra una salutació per consola. * * @author Nom de l'alumne */ public class HolaMon { /** * Mètode principal: punt d'entrada del programa. * * @param args arguments de la línia d'ordres (no s'utilitzen) */ public static void main(String[] args) { // Mostrem un missatge per la sortida estàndard System.out.println("Hola món!"); } }

Blocs del programa

Hi pots distingir:

  • La declaració de package.
  • La classe public class HolaMon (el fitxer s'ha de dir HolaMon.java).
  • El mètode main, que és el punt d'entrada.
  • La sentència System.out.println, que escriu un text i salta de línia.
  • Els tres tipus de comentari: //, /* */ i /** */ (Javadoc).

  • A la finestra Output apareixerà:

✅ Bones pràctiques

Un projecte per activitat, una classe per exemple. No cal crear un projecte nou per a cada exemple: a Source Packages, clic dret al paquet → New → Java Class, posa-li el nom de l'exemple i enganxa el codi a sota de la línia package. Un projecte pot tenir tantes classes amb main com vulguis: Run File (Maj+F6) executa només la que tries.

👀 Fixa't-hi

A les subpàgines següents els exemples no porten la línia package, per fer-los més curts. Quan els copiïs a NetBeans, deixa la línia package …; que ja té el fitxer i enganxa el codi a sota.

L'error «Incorrect package»

El primer error que et trobaràs (i com evitar-lo)

Quan copiem exemples d'una pàgina web a NetBeans és fàcil trepitjar la línia package. Aquest és el resultat:

BàsicFitxer HolaMon.java dins del paquet daw.aea1_a1
package daw.introducciojava; // ✘ no és el paquet on és el fitxer public class HolaMon { // ... }
Com funciona

NetBeans mostra una bombeta vermella a la línia 1 amb el missatge Incorrect package: la línia package diu daw.introducciojava, però el fitxer és a la carpeta del paquet daw.aea1_a1. Totes dues coses han de coincidir.

⚠️ Errors típics

Error Incorrect package (bombeta vermella a la línia 1). Apareix quan la línia package no coincideix amb el paquet on és el fitxer. Sol passar en enganxar un exemple i esborrar o canviar la línia package que havia escrit NetBeans.

Solució: mira el nom del paquet a Source Packages (per exemple lamerce.estructura) i escriu-lo a la primera línia: package lamerce.estructura;. També pots clicar la bombeta i triar Change package declaration to …. No triïs Move class to correct folder: mouria el fitxer a una carpeta nova.

Per evitar-ho: copia els exemples a partir de la línia import (o de public class si no n'hi ha) i enganxa'ls a sota del package que ja hi ha.
