Casos de prova

Provar tots els camins

Un programa amb alternatives té diversos camins. Per estar segurs que funciona cal provar-los tots, amb especial atenció als valors límit (o frontera), que és on s'amaguen la majoria d'errors: un < que hauria de ser <=, una condició en mal ordre…

Abans de donar per bo el programa de qualificacions de l'A2.1, preparem una taula amb un valor de cada rang i els valors frontera:

Nota de provaPer què la provemResultat esperat
-1 i 11fora de rangNota incorrecta
0 i 4.99límits d'InsuficientInsuficient
5frontera Insuficient / SuficientSuficient
6frontera Suficient / BéBé
7frontera Bé / NotableNotable
9 i 10frontera i màximExcel·lent
✅ Bones pràctiques

Com triar els casos de prova: un valor qualsevol de cada camí, els dos valors de cada frontera (el darrer d'un rang i el primer del següent) i algun valor no vàlid. Afegeix una columna Resultat obtingut i marca ✔ o ✘ després d'executar.

2

El depurador de NetBeans

Veure el programa per dins

Quan un programa dona un resultat incorrecte, el depurador (debugger) permet executar-lo línia a línia i veure el valor de les variables en cada moment. Així es veu clarament per quina branca de l'if entra.

1Posar un punt d'interrupcióFes clic al número de línia on vols aturar l'execució. Apareix un quadrat vermell (breakpoint).
2Iniciar la depuracióClic dret al fitxer → Debug File (Ctrl+Maj+F5). El programa s'atura a la línia marcada.
3Avançar pas a pasF8 executa la línia actual i passa a la següent. Observa per quin bloc de l'if entra el programa.
4Inspeccionar variablesLa finestra Variables mostra el valor de cada variable. També pots passar el ratolí per sobre d'una variable.
👀 Fixa't-hi

PSeInt també té un mode pas a pas (Ejecutar paso a paso). El depurador de NetBeans fa el mateix, però amb programes reals i amb la llista de variables sempre visible.

Documentar les decisions

Exercicis

Posa-ho tot en pràctica

Aquests dos exercicis fan servir tot el que has vist: dissenyar casos de prova amb els valors frontera, trobar un error amb el depurador de NetBeans i documentar les decisions amb comentaris i constants. Escriu-los i compara la sortida amb l'exemple d'execució.

✍️ Ara tu · Exercici 1El radar de la carreteraBàsic
1 · Llegeix l'algorisme→2 · Escriu-lo en Java→3 · Executa i compara

En una carretera limitada a 90 km/h, un radar classifica cada cotxe: fins a 90 km/h és correcte, fins a 110 km/h és multa lleu i per sobre, multa greu. Una velocitat negativa vol dir que el radar ha fallat. Tradueix l'algorisme a la classe Radar i, després, omple una taula de casos de prova.

Algoritmo Radar Definir velocitat Como Entero Definir resultat Como Cadena velocitat <- 105 Si velocitat < 0 Entonces resultat <- "Velocitat no vàlida" SiNo Si velocitat <= 90 Entonces resultat <- "Correcte" SiNo Si velocitat <= 110 Entonces resultat <- "Multa lleu" SiNo resultat <- "Multa greu" FinSi FinSi FinSi Escribir "Velocitat ", velocitat, " km/h: ", resultat FinAlgoritmo
  • Els Si niats → else if. Converteix els límits 90 i 110 en constants.
  • Fes una taula amb les columnes Velocitat, Per què la provem, Resultat esperat i Resultat obtingut.
  • Prova totes les fronteres: -1, 0, 90, 91, 110 i 111.
🖥️ Exemple d'execució
Velocitat 105 km/h: Multa lleu
✅ Solució
public class Radar { public static void main(String[] args) { final int LIMIT_VELOCITAT = 90; // km/h permesos final int LIMIT_MULTA_LLEU = 110; // fins aquí la multa és lleu int velocitat = 105; String resultat; // Primer descartem els valors impossibles if (velocitat < 0) { resultat = "Velocitat no vàlida"; } else if (velocitat <= LIMIT_VELOCITAT) { resultat = "Correcte"; } else if (velocitat <= LIMIT_MULTA_LLEU) { resultat = "Multa lleu"; } else { resultat = "Multa greu"; } System.out.println("Velocitat " + velocitat + " km/h: " + resultat); } }
✔ Què es valora
  • La traducció és correcta i fa servir else if.
  • La taula té les fronteres: -1 → no vàlida; 0 i 90 → Correcte; 91 i 110 → Multa lleu; 111 → Multa greu.
  • Cada fila té el resultat esperat i l'obtingut.
  • Els límits són constants amb nom.

1 · Llegeix l'algorisme→2 · Escriu-lo en Java→3 · Depura i corregeix

La regla de la botiga és: els clients prèmium i les compres de 50 € o més no paguen enviament; la resta paga 5 €. Però l'algorisme té un error. Tradueix-lo a Java tal com està (classe Enviament), executa'l amb una compra de 50 € i, amb el depurador, troba per quina branca entra. Després corregeix-lo i documenta la regla.

Algoritmo Enviament Definir importCompra, costEnviament, total Como Entero Definir esPremium Como Logico importCompra <- 50 esPremium <- Falso Si esPremium O importCompra > 50 Entonces costEnviament <- 0 SiNo costEnviament <- 5 FinSi total <- importCompra + costEnviament Escribir "Compra: ", importCompra, " € · enviament: ", costEnviament, " €" Escribir "Total: ", total, " €" FinAlgoritmo
  • Primer tradueix-lo sense canviar res (O → ||): amb 50 € sortirà enviament: 5 € i Total: 55 €.
  • Posa un breakpoint a la línia de l'if, avança amb F8 i mira els valors a la finestra Variables. Explica l'error en un comentari.
  • Corregeix-lo, converteix el 50 i el 5 en constants i prova amb 49, 50 i 51 € i amb un client prèmium.
🖥️ Exemple d'execució
Compra: 50 € · enviament: 0 €
Total: 50 €
✅ Solució
public class Enviament { public static void main(String[] args) { final int IMPORT_ENVIAMENT_GRATUIT = 50; // euros final int COST_ENVIAMENT = 5; // euros int importCompra = 50; boolean esPremium = false; int costEnviament; // Els clients prèmium i les compres de 50 € o més no paguen enviament. // ERROR ORIGINAL: la condició era "importCompra > 50" i una compra // de 50 € justos pagava l'enviament. Ha de ser >= (frontera inclosa). if (esPremium || importCompra >= IMPORT_ENVIAMENT_GRATUIT) { costEnviament = 0; } else { costEnviament = COST_ENVIAMENT; } int total = importCompra + costEnviament; System.out.println("Compra: " + importCompra + " € · enviament: " + costEnviament + " €"); System.out.println("Total: " + total + " €"); } }
✔ Què es valora
  • S'ha fet servir el depurador per veure la branca on entra.
  • Un comentari explica la regla i la causa de l'error (la frontera de 50 € no s'incloïa).
  • No hi ha números màgics: l'import mínim i el cost de l'enviament són constants.
  • S'han provat les fronteres 49, 50 i 51 i el client prèmium.
