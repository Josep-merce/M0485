1

Control d'excepcions

Capturar els errors amb try-catch

Una excepció és un error que es produeix mentre el programa s'executa: dividir un enter per zero, convertir un text que no és un número… Si no la controlem, el programa s'atura i mostra un missatge d'error. Amb try-catch podem capturar-la i decidir què fer.

BlocQuan s'executa
try { }Sempre. Conté el codi que podria fallar.
catch (TipusExcepcio e) { }Només si dins del try s'ha produït una excepció d'aquest tipus.
finally { }Sempre, tant si hi ha hagut excepció com si no (és opcional).
Diversos catch i finally
public class DivisioSegura { public static void main(String[] args) { String textDividend = "100"; String textDivisor = "0"; // Sense try-catch, la divisió aturaria el programa: // int resultat = 100 / 0; → ArithmeticException try { int dividend = Integer.parseInt(textDividend); int divisor = Integer.parseInt(textDivisor); int resultat = dividend / divisor; // falla si divisor és 0 System.out.println("Resultat: " + resultat); } catch (NumberFormatException e) { System.out.println("Error: algun valor no és un enter."); } catch (ArithmeticException e) { System.out.println("Error: " + e.getMessage()); } finally { System.out.println("[finally] Sempre s'executa."); } System.out.println("El programa continua..."); } }
🖥️ Sortida per consola
Error: / by zero
[finally] Sempre s'executa.
El programa continua...
Com funciona

Sense control, la divisió entera per zero aturaria el programa amb una ArithmeticException (la línia comentada). En posar-la dins del try, quan es produeix l'error Java salta al catch corresponent i el println del resultat no s'arriba a executar.

Cada catch tracta un tipus d'error: si algun text no fos un enter (per exemple "cent"), parseInt llançaria una NumberFormatException i s'executaria el primer; com que el divisor és 0, s'executa el segon. e.getMessage() retorna la descripció de l'error que dona Java: / by zero.

El bloc finally s'executa sempre, tant si hi ha hagut error com si no. I com que l'excepció s'ha capturat, el programa no s'atura: continua amb la línia que hi ha després del try-catch.

Excepció freqüentCausa habitual
ArithmeticExceptionDivisió entera per zero (5 / 0)
NumberFormatExceptionInteger.parseInt("abc")
InputMismatchExceptionsc.nextInt() quan l'usuari escriu text
NullPointerExceptionUsar una variable d'objecte que val null
ArrayIndexOutOfBoundsExceptionAccedir a una posició inexistent d'una taula (ho veurem a l'AEA3)
📌 Fixa't-hiCuriosament, 5.0 / 0 amb decimals no llança cap excepció: dona Infinity. Només la divisió entera per zero provoca ArithmeticException.

Validar dades amb un bucle

Tornar a demanar fins que la dada és correcta

Combinant un bucle amb try-catch podem tornar a demanar una dada fins que sigui correcta. És un dels patrons més útils de tot el curs.

MitjàDemanar un número fins que sigui vàlid
import java.util.Scanner; public class LlegirEnter { public static void main(String[] args) { Scanner sc = new Scanner(System.in); int numero = 0; boolean valid = false; while (!valid) { System.out.print("Escriu un número enter: "); String text = sc.nextLine(); try { numero = Integer.parseInt(text); valid = true; // només arribem aquí si no hi ha error } catch (NumberFormatException e) { System.out.println("'" + text + "' no és un enter. Torna-ho a provar."); } } System.out.println("Has escrit el " + numero + ". El doble és " + numero * 2); sc.close(); } }
🖥️ Exemple d'execució
Escriu un número enter: hola
'hola' no és un enter. Torna-ho a provar.
Escriu un número enter: 4.5
'4.5' no és un enter. Torna-ho a provar.
Escriu un número enter: 21
Has escrit el 21. El doble és 42

Llançar excepcions i crear-ne de pròpies

Quan la dada és incorrecta per a nosaltres

També podem llançar nosaltres una excepció quan detectem una dada incorrecta, amb throw new TipusExcepcio("missatge"). Podem fer servir una de les moltes excepcions predefinides de Java, com IllegalArgumentException, però de vegades volem una excepció amb un nom que expliqui exactament el problema del nostre programa: SaldoInsuficientException, NotaInvalidaException… Per crear-la, definim una classe que hereta d'Exception.

📌 No et preocupis per extends, super i els constructorsSón conceptes de programació orientada a objectes que estudiarem a l'AEA2 i l'AEA3. De moment, fes servir aquesta plantilla canviant només el nom de la classe: class NomException extends Exception { public NomException(String missatge) { super(missatge); } }
Llançar una excepció predefinida i una de pròpia
// Excepció pròpia: es pot escriure al mateix fitxer, fora de la classe principal class NotaInvalidaException extends Exception { public NotaInvalidaException(String missatge) { super(missatge); } } public class ValidarDades { // "throws" avisa que el main pot llançar aquesta excepció public static void main(String[] args) throws NotaInvalidaException { // 1. Llançar una excepció predefinida de Java int edat = -4; try { if (edat < 0 || edat > 120) { throw new IllegalArgumentException("Edat fora de rang: " + edat); } System.out.println("Edat correcta: " + edat); } catch (IllegalArgumentException e) { System.out.println("Error: " + e.getMessage()); } // 2. Llançar la nostra excepció double nota = 11.5; try { if (nota < 0 || nota > 10) { throw new NotaInvalidaException("La nota " + nota + " no és entre 0 i 10"); } System.out.println("Nota registrada: " + nota); } catch (NotaInvalidaException e) { System.out.println("Error: " + e.getMessage()); } } }
🖥️ Sortida per consola
Error: Edat fora de rang: -4
Error: La nota 11.5 no és entre 0 i 10
Com funciona

En tots dos casos el throw va dins d'un if que detecta la dada incorrecta. Quan s'executa, Java salta directament al catch: el println que hi ha després del if no s'arriba a executar, i el missatge que hem passat en crear l'excepció es recupera amb e.getMessage().

La primera excepció és predefinida (IllegalArgumentException) i la segona és nostra: NotaInvalidaException només és una classe que hereta d'Exception i passa el missatge amb super. Es captura igual que qualsevol altra.

Tipus d'excepcióHereta deObligació
Comprovada (checked)ExceptionEl compilador obliga a capturar-la amb try-catch o declarar-la amb throws.
No comprovada (unchecked)RuntimeExceptionNo és obligatori capturar-la. Ex.: ArithmeticException, NumberFormatException.

Aquest programa reparteix caramels entre uns nens a parts iguals i diu quants en sobren. Funciona si l'usuari escriu bé les dades, però s'atura amb una excepció si escriu un text que no és un número o si diu que hi ha 0 nens. Copia'l a la classe RepartirCaramels i protegeix-lo.

import java.util.Scanner; public class RepartirCaramels { public static void main(String[] args) { Scanner sc = new Scanner(System.in); System.out.print("Caramels: "); String textCaramels = sc.nextLine(); System.out.print("Nens: "); String textNens = sc.nextLine(); int caramels = Integer.parseInt(textCaramels); int nens = Integer.parseInt(textNens); System.out.println("Cada nen en rep " + caramels / nens + " i en sobren " + caramels % nens + "."); sc.close(); } }
  • Posa les conversions i els càlculs dins d'un try.
  • Afegeix un catch per a la NumberFormatException i un altre per a l'ArithmeticException, cadascun amb el seu missatge.
  • Afegeix un finally que mostri Repartiment acabat. i prova-ho amb vint, amb 0 nens i amb 25 caramels i 4 nens.
🖥️ Exemple d'execució
Caramels: 25
Nens: 0
Error: no hi ha cap nen.
Repartiment acabat.
✅ Solució
import java.util.Scanner; // Reparteix caramels entre uns nens, controlant els errors public class RepartirCaramels { public static void main(String[] args) { Scanner sc = new Scanner(System.in); System.out.print("Caramels: "); String textCaramels = sc.nextLine(); System.out.print("Nens: "); String textNens = sc.nextLine(); try { int caramels = Integer.parseInt(textCaramels); // NumberFormatException si no és un enter int nens = Integer.parseInt(textNens); int perNen = caramels / nens; // ArithmeticException si nens és 0 int sobren = caramels % nens; System.out.println("Cada nen en rep " + perNen + " i en sobren " + sobren + "."); } catch (NumberFormatException e) { System.out.println("Error: has d'escriure números enters."); } catch (ArithmeticException e) { System.out.println("Error: no hi ha cap nen."); } finally { System.out.println("Repartiment acabat."); } sc.close(); } }
✔ Què es valora
  • Només el codi que pot fallar és dins del try.
  • Cada tipus d'error té el seu catch i un missatge que l'usuari entén.
  • El finally s'executa en els tres casos.
  • Amb 25 caramels i 4 nens surt Cada nen en rep 6 i en sobren 1.

1 · Llegeix l'enunciat→2 · Escriu-lo en Java→3 · Executa i prova

Per a l'obra de teatre de l'institut només queden 4 entrades. Escriu la classe ReservaEntrades, que demana quantes entrades es volen i torna a preguntar fins que la quantitat és vàlida. Si l'usuari escriu un text, si demana 0 entrades o menys, o si en demana més de les que queden, ha de veure un missatge diferent per a cada cas. Quan la quantitat és correcta, mostra la reserva i les entrades que queden.

  • Fes un bucle amb try-catch i Integer.parseInt(), com a l'apartat 2, i guarda les entrades que queden en una constant final.
  • Si la quantitat és 0 o menys, llança una IllegalArgumentException amb throw.
  • Si en demana més de les que queden, llança una excepció pròpia LimitEntradesException creada amb la plantilla de l'apartat 3. Vigila l'ordre dels catch.
🖥️ Exemple d'execució
Quantes entrades vols? tres
'tres' no és un número enter.
Quantes entrades vols? 0
Has de demanar almenys una entrada.
Quantes entrades vols? 6
No hi ha prou entrades. Només en queden 4.
Quantes entrades vols? 3
Reserva feta: 3 entrades. En queden 1.
✅ Solució
import java.util.Scanner; // Excepció pròpia: es demanen més entrades de les que queden class LimitEntradesException extends Exception { public LimitEntradesException(String missatge) { super(missatge); } } // Demana quantes entrades es volen fins que la quantitat és vàlida public class ReservaEntrades { public static void main(String[] args) { Scanner sc = new Scanner(System.in); final int DISPONIBLES = 4; int entrades = 0; boolean valida = false; while (!valida) { System.out.print("Quantes entrades vols? "); String text = sc.nextLine(); try { entrades = Integer.parseInt(text); if (entrades <= 0) { throw new IllegalArgumentException("Has de demanar almenys una entrada."); } if (entrades > DISPONIBLES) { throw new LimitEntradesException("Només en queden " + DISPONIBLES + "."); } valida = true; // només arribem aquí si no hi ha cap error } catch (NumberFormatException e) { // primer: hereta d'IllegalArgumentException System.out.println("'" + text + "' no és un número enter."); } catch (IllegalArgumentException e) { System.out.println(e.getMessage()); } catch (LimitEntradesException e) { System.out.println("No hi ha prou entrades. " + e.getMessage()); } } System.out.println("Reserva feta: " + entrades + " entrades. En queden " + (DISPONIBLES - entrades) + "."); sc.close(); } }
✔ Què es valora
  • El bucle només acaba quan la quantitat és correcta.
  • Es fa servir throw tant per a l'excepció predefinida com per a la pròpia, que hereta d'Exception.
  • L'ordre dels catch és correcte: NumberFormatException va abans d'IllegalArgumentException, perquè n'hereta.
  • Cada error mostra el seu missatge i la sortida coincideix amb l'exemple.
