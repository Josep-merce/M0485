Control d'excepcions

Capturar els errors amb try-catch

Una excepció és un error que es produeix mentre el programa s'executa: dividir un enter per zero, convertir un text que no és un número… Si no la controlem, el programa s'atura i mostra un missatge d'error. Amb try-catch podem capturar-la i decidir què fer.

BlocQuan s'executa
try { }Sempre. Conté el codi que podria fallar.
catch (TipusExcepcio e) { }Només si dins del try s'ha produït una excepció d'aquest tipus.
finally { }Sempre, tant si hi ha hagut excepció com si no (és opcional).
Diversos catch i finally
public class DivisioSegura { public static void main(String[] args) { String textDividend = "100"; String textDivisor = "0"; // Sense try-catch, la divisió aturaria el programa: // int resultat = 100 / 0; → ArithmeticException try { int dividend = Integer.parseInt(textDividend); int divisor = Integer.parseInt(textDivisor); int resultat = dividend / divisor; // falla si divisor és 0 System.out.println("Resultat: " + resultat); } catch (NumberFormatException e) { System.out.println("Error: algun valor no és un enter."); } catch (ArithmeticException e) { System.out.println("Error: " + e.getMessage()); } finally { System.out.println("[finally] Sempre s'executa."); } System.out.println("El programa continua..."); } }
🖥️ Sortida per consola
Error: / by zero
[finally] Sempre s'executa.
El programa continua...
Com funciona

Sense control, la divisió entera per zero aturaria el programa amb una ArithmeticException (la línia comentada). En posar-la dins del try, quan es produeix l'error Java salta al catch corresponent i el println del resultat no s'arriba a executar.

Cada catch tracta un tipus d'error: si algun text no fos un enter (per exemple "cent"), parseInt llançaria una NumberFormatException i s'executaria el primer; com que el divisor és 0, s'executa el segon. e.getMessage() retorna la descripció de l'error que dona Java: / by zero.

El bloc finally s'executa sempre, tant si hi ha hagut error com si no. I com que l'excepció s'ha capturat, el programa no s'atura: continua amb la línia que hi ha després del try-catch.

Excepció freqüentCausa habitual
ArithmeticExceptionDivisió entera per zero (5 / 0)
NumberFormatExceptionInteger.parseInt("abc")
InputMismatchExceptionsc.nextInt() quan l'usuari escriu text
NullPointerExceptionUsar una variable d'objecte que val null
ArrayIndexOutOfBoundsExceptionAccedir a una posició inexistent d'una taula (ho veurem a l'AEA3)
📌 Fixa't-hiCuriosament, 5.0 / 0 amb decimals no llança cap excepció: dona Infinity. Només la divisió entera per zero provoca ArithmeticException.

Aquest programa reparteix uns punts entre els jugadors, però té dos problemes: el text "8,5" no és un enter i hi ha 0 jugadors. Si l'executes, s'atura amb una excepció. Copia'l a la classe PuntsPerJugador i protegeix-lo.

public class PuntsPerJugador { public static void main(String[] args) { String textPunts = "8,5"; int jugadors = 0; int punts = Integer.parseInt(textPunts); int perJugador = punts / jugadors; System.out.println("Punts per jugador: " + perJugador); } }
✅ Solució
// Reparteix uns punts entre els jugadors, controlant els errors public class PuntsPerJugador { public static void main(String[] args) { String textPunts = "8,5"; int jugadors = 0; try { int punts = Integer.parseInt(textPunts); // NumberFormatException si no és un enter int perJugador = punts / jugadors; // ArithmeticException si jugadors és 0 System.out.println("Punts per jugador: " + perJugador); } catch (NumberFormatException e) { System.out.println("Error: '" + textPunts + "' no és un número enter."); } catch (ArithmeticException e) { System.out.println("Error: no hi ha cap jugador."); } finally { System.out.println("Càlcul acabat."); } } }
✔ Què es valora
  • Cada tipus d'error té el seu catch i el seu missatge.
  • El finally s'executa en els tres casos.
  • Amb "85" i 4 jugadors surt Punts per jugador: 21 (divisió entera).
  • Posa el codi que pot fallar dins d'un try.
  • Afegeix un catch per a la NumberFormatException i un altre per a l'ArithmeticException, cadascun amb el seu missatge.
  • Afegeix un finally que mostri Càlcul acabat.
  • Prova-ho tres vegades: amb "8,5"; amb "85" i 0 jugadors; i amb "85" i 4 jugadors.
💡 Pista
Executa primer el programa sense canviar res i llegeix el missatge d'error de la consola: el nom de l'excepció és el que has de posar al catch.

Càlcul acabat.

Validar dades amb un bucle

Tornar a demanar fins que la dada és correcta

Combinant un bucle amb try-catch podem tornar a demanar una dada fins que sigui correcta. És un dels patrons més útils de tot el curs.

MitjàDemanar un número fins que sigui vàlid
import java.util.Scanner; public class LlegirEnter { public static void main(String[] args) { Scanner sc = new Scanner(System.in); int numero = 0; boolean valid = false; while (!valid) { System.out.print("Escriu un número enter: "); String text = sc.nextLine(); try { numero = Integer.parseInt(text); valid = true; // només arribem aquí si no hi ha error } catch (NumberFormatException e) { System.out.println("'" + text + "' no és un enter. Torna-ho a provar."); } } System.out.println("Has escrit el " + numero + ". El doble és " + numero * 2); sc.close(); } }
🖥️ Exemple d'execució
Escriu un número enter: hola
'hola' no és un enter. Torna-ho a provar.
Escriu un número enter: 4.5
'4.5' no és un enter. Torna-ho a provar.
Escriu un número enter: 21
Has escrit el 21. El doble és 42
✍️ Ara tu · Exercici 2 Llegir una edat vàlida Mitjà

Demana l'edat a l'usuari fins que escrigui un número enter entre 0 i 120. Si escriu text, mostra un missatge d'error; si el número és fora de rang, un missatge diferent.

  • Fes servir un bucle amb try-catch i Integer.parseInt().
  • Captura la NumberFormatException.
  • Per al rang, pots fer un simple if o llançar una IllegalArgumentException amb throw.
  • Al final, mostra l'edat i si és major d'edat.
✅ Solució
import java.util.Scanner; public class LlegirEdat { public static void main(String[] args) { Scanner sc = new Scanner(System.in); int edat = -1; boolean correcta = false; while (!correcta) { System.out.print("Quina edat tens? "); String text = sc.nextLine(); try { edat = Integer.parseInt(text); if (edat < 0 || edat > 120) { throw new IllegalArgumentException("L'edat ha de ser entre 0 i 120."); } correcta = true; } catch (NumberFormatException e) { System.out.println("'" + text + "' no és un número enter."); } catch (IllegalArgumentException e) { System.out.println(e.getMessage()); } } String tipus = (edat >= 18) ? "major" : "menor"; System.out.println("Tens " + edat + " anys: ets " + tipus + " d'edat."); sc.close(); } }
✔ Què es valora
  • El bucle només acaba quan la dada és correcta.
  • Cada tipus d'error té el seu missatge.
  • L'ordre dels catch és correcte: NumberFormatException hereta d'IllegalArgumentException, per això ha d'anar primer.
🖥️ Exemple d'execució
Quina edat tens? divuit
'divuit' no és un número enter.
Quina edat tens? 150
L'edat ha de ser entre 0 i 120.
Quina edat tens? 18
Tens 18 anys: ets major d'edat.

Llançar excepcions amb throw

Quan la dada és incorrecta per a nosaltres

També podem llançar nosaltres una excepció quan detectem una dada incorrecta, amb throw new TipusExcepcio("missatge").

MitjàLlançar una excepció si una dada no és vàlida
public class ValidarEdat { public static void main(String[] args) { int edat = -4; try { if (edat < 0 || edat > 120) { throw new IllegalArgumentException("Edat fora de rang: " + edat); } System.out.println("Edat correcta: " + edat); } catch (IllegalArgumentException e) { System.out.println("Error: " + e.getMessage()); } } }
✍️ Ara tu · Exercici 3Temperatura impossibleBàsic

Cap temperatura pot ser inferior al zero absolut (−273,15 °C). Escriu la classe Temperatura: si els graus són més baixos, ha de llançar una IllegalArgumentException; si són correctes, ha de mostrar-los convertits a Fahrenheit (°F = °C · 9 / 5 + 32).

  • Declara double graus = -300.0; i el zero absolut com a constant final.
  • Llança l'excepció amb un missatge que inclogui el valor incorrecte, i captura-la per mostrar-lo.
  • Prova-ho també amb 25.0: ha de sortir 25.0 °C = 77.0 °F.
✅ Solució
// Valida una temperatura: per sota del zero absolut no té sentit public class Temperatura { public static void main(String[] args) { final double ZERO_ABSOLUT = -273.15; double graus = -300.0; try { if (graus < ZERO_ABSOLUT) { throw new IllegalArgumentException( "Temperatura impossible: " + graus + " °C és per sota del zero absolut."); } double fahrenheit = graus * 9 / 5 + 32; System.out.println(graus + " °C = " + fahrenheit + " °F"); } catch (IllegalArgumentException e) { System.out.println("Error: " + e.getMessage()); } } }
✔ Què es valora
  • El throw és dins del try i el missatge es recupera amb getMessage().
  • Si es llança l'excepció, el càlcul de Fahrenheit no s'executa.
  • El zero absolut és una constant amb final.
💡 Pista
Fixa't en l'exemple Llançar una excepció si una dada no és vàlida: el throw va dins d'un if i el càlcul va després.
🖥️ Sortida esperada

Crear excepcions pròpies

Una excepció amb el nom del nostre problema

Java té moltes excepcions predefinides, però de vegades volem una excepció amb un nom que expliqui exactament el problema del nostre programa: SaldoInsuficientException, NotaInvalidaException… Per crear-la, definim una classe que hereta d'Exception.

📌 No et preocupis per extends, super i els constructorsSón conceptes de programació orientada a objectes que estudiarem a l'AEA2 i l'AEA3. De moment, fes servir aquesta plantilla canviant només el nom de la classe: class NomException extends Exception { public NomException(String missatge) { super(missatge); } }
MitjàExcepció pròpia per a notes incorrectes
// Excepció pròpia: es pot escriure al mateix fitxer, fora de la classe principal class NotaInvalidaException extends Exception { public NotaInvalidaException(String missatge) { super(missatge); } } public class ValidadorNota { // "throws" avisa que el main pot llançar aquesta excepció public static void main(String[] args) throws NotaInvalidaException { double nota = 11.5; try { if (nota < 0 || nota > 10) { throw new NotaInvalidaException("La nota " + nota + " no és entre 0 i 10"); } System.out.println("Nota registrada: " + nota); } catch (NotaInvalidaException e) { System.out.println("Error: " + e.getMessage()); } } }
🖥️ Sortida per consola
Error: La nota 11.5 no és entre 0 i 10
Tipus d'excepcióHereta deObligació
Comprovada (checked)ExceptionEl compilador obliga a capturar-la amb try-catch o declarar-la amb throws.
No comprovada (unchecked)RuntimeExceptionNo és obligatori capturar-la. Ex.: ArithmeticException, NumberFormatException.
✍️ Ara tu · Exercici 4 Caixer amb excepció pròpia Mitjà

Simula un compte bancari amb 200 € de saldo al qual es fan tres reintegraments: 50 €, 180 € i 30 €. Si un reintegrament supera el saldo, s'ha de llançar una excepció pròpia SaldoInsuficientException i el saldo no canvia.

  • Crea la classe SaldoInsuficientException seguint la plantilla de l'apartat 4.
  • Fes un for de 3 iteracions; l'import de cada reintegrament es pot calcular amb un switch sobre el número d'iteració.
  • Dins del bucle, un try-catch per a cada reintegrament; al finally, mostra el saldo actual.
✅ Solució
class SaldoInsuficientException extends Exception { public SaldoInsuficientException(String missatge) { super(missatge); } } public class Caixer { public static void main(String[] args) { double saldo = 200.0; for (int operacio = 1; operacio <= 3; operacio++) { // Import de cada reintegrament double quantitat = switch (operacio) { case 1 -> 50.0; case 2 -> 180.0; default -> 30.0; }; try { if (quantitat > saldo) { throw new SaldoInsuficientException( "No es poden retirar " + quantitat + " €: saldo insuficient."); } saldo -= quantitat; System.out.println("Retirats " + quantitat + " €."); } catch (SaldoInsuficientException e) { System.out.println("Error: " + e.getMessage()); } finally { System.out.println(" Saldo actual: " + saldo + " €"); } } } }
✔ Què es valora
  • L'excepció pròpia hereta d'Exception i passa el missatge amb super.
  • Quan hi ha error el saldo no es modifica (el saldo -= quantitat va després del throw).
  • El finally s'executa en tots els casos.
🖥️ Sortida esperada
Retirats 50.0 €.
  Saldo actual: 150.0 €
Error: No es poden retirar 180.0 €: saldo insuficient.
  Saldo actual: 150.0 €
Retirats 30.0 €.
  Saldo actual: 120.0 €
